# 온라인 섯다 (최대 6인)

친구들끼리 가상 칩으로 즐기는 실시간 온라인 섯다(화투 카드 게임) 웹 서비스입니다.
**실제 돈이 오가지 않습니다** — 관리자가 발급한 계정으로 로그인해서 가상 칩으로만 플레이합니다.

- 실제 배포 주소: (Vercel/Render 배포 후 여기에 기록)
- 최대 6명이 한 방에서 동시 플레이 (2명부터 시작 가능)
- 모바일 세로 화면 기준으로 최적화된 UI

---

## 1. 이게 뭐 하는 프로젝트인가요?

전통 카드 게임인 "섯다"를 온라인으로 구현한 웹앱입니다. 참가자들은:

1. 관리자가 만들어준 아이디/비밀번호로 로그인하고
2. 로비에서 방을 만들거나 방 코드로 입장한 뒤
3. 같은 방 사람들과 실시간으로 섯다를 칩니다 (카드 배분 → 베팅 → 쇼다운)

일반 홈페이지처럼 새로고침해서 정보를 갱신하는 방식이 아니라, **Socket.IO**로 서버와 실시간 양방향 통신을 하기 때문에 상대방이 베팅하거나 카드를 받는 순간 화면이 바로 갱신됩니다.

---

## 2. 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 클라이언트 | React + TypeScript + Vite, React Router, socket.io-client |
| 서버 | Node.js + TypeScript, Express(REST API), Socket.IO(실시간 통신) |
| 데이터베이스 | PostgreSQL (Prisma ORM으로 접근) |
| 인증 | JWT (일반 사용자용 / 관리자용 토큰 분리) |
| 배포 | 클라이언트 = Vercel, 서버 = Render, DB = Prisma Postgres |

**왜 프론트/백엔드를 나눠서 배포하나요?**
Vercel은 서버리스(요청 있을 때만 잠깐 실행) 방식이라 Socket.IO 같은 "계속 연결을 유지하는" 서버를 못 올립니다. 그래서 화면(클라이언트)만 Vercel에 올리고, 실시간 서버(백엔드)는 상시 구동되는 Render에 따로 올립니다.

## 3. 폴더 구조

이 저장소는 **모노레포**(하나의 저장소에 프론트/백엔드를 같이 관리) 구조입니다.

```
├── client/                 # 프론트엔드 (React)
│   ├── src/
│   │   ├── pages/          # 화면 단위 컴포넌트 (로그인, 로비, 게임, 관리자 등)
│   │   ├── components/     # 게임판을 구성하는 조각 컴포넌트 (카드, 좌석, 베팅버튼 등)
│   │   ├── api/            # 서버 REST API 호출 함수
│   │   ├── socket.ts       # Socket.IO 연결 관리
│   │   └── AuthContext.tsx # 로그인 상태 전역 관리
│   └── public/cards/       # 화투 카드 이미지
│
├── server/                 # 백엔드 (Node.js)
│   ├── src/
│   │   ├── game/           # 섯다 게임 엔진 (핵심 로직)
│   │   │   ├── Room.ts         # 방 하나의 상태머신 (대기→배팅→쇼다운→결과)
│   │   │   ├── handRank.ts     # 족보 판정 로직
│   │   │   ├── deck.ts         # 카드 덱 생성/셔플
│   │   │   └── RoomManager.ts  # 여러 방을 관리
│   │   ├── auth/            # 일반 사용자 로그인
│   │   ├── admin/           # 관리자 전용 API
│   │   ├── socket/          # Socket.IO 이벤트 처리
│   │   └── index.ts         # 서버 진입점
│   └── prisma/
│       ├── schema.prisma    # DB 테이블 정의
│       └── migrations/      # DB 변경 이력
│
└── Cards/                  # 원본 화투 카드 이미지 (client/public/cards로 복사되어 사용됨)
```

## 4. 로컬에서 실행하는 방법

### 준비물
- Node.js 설치
- PostgreSQL 접속 정보 (직접 설치하거나, [Prisma Postgres](https://www.prisma.io/postgres) 같은 무료 호스팅 DB 사용)

### 순서

```bash
# 1. 의존성 설치 (루트에서 한 번만)
npm install

# 2. server 폴더에 .env 파일 생성 (아래 "환경변수" 표 참고)

# 3. DB 테이블 생성 (최초 1회, 또는 schema.prisma 변경 시)
npm run prisma:migrate

# 4. 서버 + 클라이언트 동시 실행
npm run dev
```

- 클라이언트: http://localhost:5173
- 서버: http://localhost:4000

### 환경변수 (`server/.env`)

| 변수명 | 설명 | 예시 |
|---|---|---|
| `DATABASE_URL` | PostgreSQL 접속 문자열 | `postgres://user:pw@host:5432/db?sslmode=require` |
| `JWT_SECRET` | 로그인 토큰 서명용 비밀키 (아무 긴 랜덤 문자열) | `31a24ea9e8fe...` |
| `PORT` | 서버 포트 (로컬 개발용, **배포 환경에서는 설정하지 말 것**) | `4000` |
| `CLIENT_ORIGIN` | 클라이언트 주소 (CORS 허용용) | `http://localhost:5173` |
| `ADMIN_PASSWORD` | 관리자 페이지 로그인 비밀번호 | 원하는 값 |

클라이언트 쪽(`client/.env.local`, 선택사항)에는 `VITE_SERVER_URL`로 서버 주소를 지정할 수 있습니다 (안 넣으면 `http://localhost:4000` 사용).

⚠️ **`.env` 파일들은 git에 올라가지 않습니다** (비밀번호/DB 접속정보 보호). 새 PC에서 작업하려면 직접 다시 만들어야 합니다.

## 5. 배포 구조

```
사용자 브라우저
     │
     ▼
[Vercel] 프론트엔드 (client/)  ──── API/Socket.IO 요청 ────▶  [Render] 백엔드 (server/)
                                                                    │
                                                                    ▼
                                                          [Prisma Postgres] 데이터베이스
```

- GitHub 저장소(`wonsmm2/adgambling`)의 `main` 브랜치에 push되면 Vercel과 Render가 **자동으로 재배포**합니다.
- 배포 순서(처음 세팅할 때만): Render(백엔드) 먼저 배포 → 주소 확인 → Vercel 환경변수(`VITE_SERVER_URL`)에 그 주소 입력 → Vercel 배포 → 받은 Vercel 주소를 다시 Render의 `CLIENT_ORIGIN`에 입력.

## 6. 플레이 방법

1. **로그인**: 회원가입 기능은 없습니다. 관리자가 관리자 페이지(`/admin`)에서 계정을 만들어줘야 합니다.
2. **로비**: "새 방 만들기" 또는 남이 만든 "방 코드"로 입장
3. **대기**: 같은 방 사람들(2~6명)이 모두 "준비 완료"를 누르면 자동으로 한 판이 시작됩니다
4. **진행**: 카드 1장 배분 → 1라운드 베팅 → 카드 1장 더 배분(총 2장) → 2라운드 베팅 → 쇼다운(패 공개)
5. **베팅 액션**: 삥 / 하프 / 콜 / 체크 / 다이
6. **결과**: 가장 높은 족보를 가진 사람이 팟을 가져갑니다 (동점이면 "나가리"로 동점자끼리 재대결)

## 7. 관리자 페이지 (`/admin`)

`server/.env`의 `ADMIN_PASSWORD`로 로그인합니다. 할 수 있는 것:
- **회원 목록 조회**: 전체 가입자와 보유 칩 확인
- **회원 추가**: 아이디/비밀번호/시작 칩을 직접 지정해서 계정 생성
- **칩 수정**: 특정 회원의 칩을 원하는 값으로 변경
- **비밀번호 초기화**: 회원이 비밀번호를 잊어버렸을 때 새 비밀번호로 재설정
- **회원 삭제**

## 8. 섯다 규칙 (본 구현 기준, 나무위키 표준룰 참고)

- 화투 20장(1~10월, 월별 그림 1장 + 띠 1장) 사용
- 족보(높은 순):
  1. 38광땡(3월광+8월광)
  2. 18광땡 = 13광땡 (동급)
  3. 땡: 장땡(10땡) ~ 1땡
  4. 중간족보: 알리(1+2) > 독사(1+4) > 구삥(1+9) > 장삥(1+10) > 장사(4+10) > 세륙(4+6)
  5. 끗: 갑오(9끗) ~ 망통(0끗)
- **특수 조합(잡이)**: 암행어사(4월그림+7월그림)는 상대 중 13/18광땡 보유자가 있을 때만 활성화되어 그 사이 등급으로 승리 (타깃 없으면 1끗). 땡잡이(3월광+7월그림)는 상대 중 1~9땡 보유자가 있을 때만 활성화되어 9땡과 장땡 사이 등급으로 승리 (타깃 없으면 망통). 장땡·38광땡은 잡이에 영향받지 않음
- **강제 재대결**: 구사(4월+9월)를 든 사람이 있는데 최고패가 알리 이하면 폴드 안 한 전원이 재대결. 멍텅구리구사(4월그림+9월그림)는 최고패가 9땡 이하일 때 전원 재대결(광땡·장땡 제외)
- **동점(나가리)**: 같은 등급이면 동점자끼리만 카드를 새로 받아 재대결 (안테 재징수 없음, 카드 2장 바로 배분 후 베팅 1회)
- **베팅 금액**: 안테(게임 시작 시 기본 판돈) 1,000칩. 삥은 이전 배팅금액+1,000칩(이미 배팅이 시작됐으면 사용 불가), 하프는 배팅 전이면 1,000칩 · 배팅이 있으면 이전 배팅금액+2,000칩. (`server/src/config.ts`에서 값 조정 가능)
- **아직 구현 안 된 것**: 땡값(추가 배당), 광박/멍박, 흔들기, 사이드팟(올인 시 초과분은 단순화되어 메인 팟에 그대로 포함)

## 9. 알려진 제한사항 / 다음에 할 만한 것

- 계정당 세션 1개만 허용 (다른 기기/브라우저에서 로그인하면 기존 세션은 로그아웃됨)
- 다이한 사람이 구사/멍구사 재대결에 돈 내고 참여하는 기능은 미구현
- 무료 티어(Render) 사용 시 일정 시간 미접속하면 서버가 잠들어서 첫 접속이 느릴 수 있음
